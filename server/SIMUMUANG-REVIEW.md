## สัญญาข้อมูล

- ตรวจรหัส `_id` และ `th.name` ตรงกันเท่านั้น ไม่ fallback ตามคำบางส่วน
- ขนาด small/medium/large แยกกัน เก็บค่าต้นทางใน `sizes[].raw`
- status: valid (0 < min <= max), invalid_range, incomplete_range (ศูนย์ด้านเดียว),
  missing_price (ไม่มีขนาด หรือ 0/0), invalid_value (ชนิดผิด/ขาดปลายช่วง/ค่าติดลบ)
- ไม่รวมต่างขนาด ถ้ามีหลายขนาด valid และยังไม่ยืนยันขนาด คืน size_selection_required
  ถ้าขนาดที่ยืนยันไม่ผ่าน จะไม่เปลี่ยนไปใช้ขนาดอื่นเอง แต่เก็บทุกขนาดไว้ให้ตรวจ
- เมื่อยืนยันสินค้าหลักและมีเพียงขนาดเดียว valid ใช้ขนาดนั้นและระบุ selectedSize/size
- หน่วยต้องมี th.name=กิโลกรัม และ en.name=kg ตรงกัน ไม่คาดเดาหน่วยที่หายไป
- isShow/isActive เป็นข้อมูลประกอบ ไม่กรอง isShow; price.updatedAt และ action_date แยกกัน
- แยก quality.status=valid จาก freshness; ใช้นโยบายทดลองตามตารางด้านล่าง
- ฟิลด์ min/max/mid/unit/source เดิมยังอยู่เมื่อ available:true เพิ่ม candidates/sizes/status/
  reasons/dataCompleteness; API envelope /api/prices และ /api/simumuang คงเดิม
- ปรับส่วนรายการตลาดใน Frontend ให้แสดงขนาดสินค้า เหตุผลที่ปฏิเสธราคา และ
  รายละเอียดแยกขนาดแบบเปิดดูได้ โดยรักษาหน้าและ API เดิม

## Pagination และประวัติ

ใช้ URL และ query เดิม page/limit=20 ตรวจ totalPages/total/currentPage/perPage/itemCount
และจำนวนรายหน้ารวมทั้งรหัสซ้ำ จำกัด 60 หน้า เว้น 500 ms ระหว่างหน้า ไม่มี retry อัตโนมัติ
การโหลดไม่ครบ/metadata เปลี่ยน/HTTP หรือ JSON ผิดพลาด คืน incomplete_data ไม่แคชเป็นผลสำเร็จ
snapshot เก่าที่หมดอายุไม่ถูกนำกลับมาแสดงเป็นข้อมูลใหม่หากการโหลดรอบใหม่ล้มเหลว
metadata complete หมายถึงหน้าที่อ่านและจำนวนตรงกัน ไม่รับรอง atomic snapshot

ตลาดที่ไม่ผ่านการตรวจไม่เข้าราคากลาง หากตลาดหนึ่งโหลดไม่ครบหรือราคาผิดเกณฑ์
ยังใช้และบันทึกราคาของอีกตลาดที่ผ่านได้ sourceCount ระบุเฉพาะตลาดที่ใช้จริง
ประวัติเดิมไม่ถูกแก้/ลบ ฟังก์ชันบันทึกตรวจทุกตลาดซ้ำและตรวจค่าเฉลี่ยก่อนเขียน
สี่มุมเมืองต้องมี validated/ขนาด/หน่วย/complete และ freshness=current
ข้อมูลใหม่ schemaVersion=2 เก็บ markets พร้อมรหัส ชื่อ ขนาด หน่วย min/max/mid
sourceUpdatedAt, action_date, fetchedAt, quality และ freshness ค่าที่ไม่มีจริงเก็บ null
วันละหนึ่งรายการต่อพืชตาม Asia/Bangkok ถ้าวันนั้นมีข้อมูลเก่าหรือใหม่แล้วจะข้าม
ไม่เขียนทับ ไม่ตัดทิ้งเมื่อเกิน 5000 รายการ และไม่แก้ in-memory history หากเขียนไฟล์ล้มเหลว
ข้อแลกเปลี่ยน: หากบันทึกตลาดเดียวไปแล้ว จะไม่เพิ่มตลาดที่กลับมาสำเร็จภายหลังในวันเดียวกัน

## การทดสอบ

รัน `node server/simumuang.test.js` เพื่อเห็นรายกรณี (node --test ในสภาพแวดล้อมนี้
เคยรายงานเป็น 1 file-level test) และ `node --check server/server.js`, `npm run build`,
`git diff --check` fixtures เป็นข้อมูลจริงที่ตัดเหลือฟิลด์ที่เกี่ยวข้อง ไม่ถูกโหลดโดย server
ราคาสังเคราะห์ใน tests ไม่ถูกนำไปใช้ในโปรแกรมจริง

## การเปลี่ยนความคาดหวังจาก 32 กรณีเดิม

ก่อนแก้ รัน 32 กรณีเดิมผ่านครบ หลังแก้รักษา 32 สถานการณ์หลักพร้อมปรับกรณีที่ขัดข้อกำหนดใหม่:
ไม่รับช่วงปลายเดียว ไม่รวมขนาด ไม่ยอมให้ ID ซ้ำ ไม่เลือกสินค้าหลักจากลำดับ API
และไม่ใช้ชื่อสะกดคล้ายอย่างคึ่นช่ายแทนรหัส+ชื่อจริงโดยอัตโนมัติ

## นโยบายทดลอง freshness และการตรวจทุกตลาด

ทุกตลาดต้องมี min/max/mid เป็นชนิด number finite และบวก min<=max,
mid อยู่ในช่วงและเท่ากับ midpoint ที่ปัดทศนิยมสองตำแหน่ง หน่วยต้องเป็นบาท/กก.
ไม่ยอมรับ Boolean หรือข้อความตัวเลขในผลตลาด (ตัวแยกต้นทางแปลงข้อความที่ตรวจแล้วเป็น Number)

ใช้ price.updatedAt เป็นเวลาระเบียนราคาต้นทาง แยก action_date และ fetchedAt เสมอ
API root updatedAt คงไว้เป็นเวลาประมวลผลเพื่อความเข้ากันได้ ห้ามตีความเป็นเวลาราคาต้นทาง
- current: วันเดียวกับปัจจุบันตาม Asia/Bangkok อายุไม่เกิน 24 ชั่วโมง
- stale: ไม่ current แต่ยังอายุไม่เกิน 48 ชั่วโมง แสดงราคาเก่า ไม่คำนวณ/บันทึก
- expired: เกิน 48 ชั่วโมง ไม่คำนวณ/บันทึก
- invalid_timestamp: ขาดเวลา เวลาไม่ถูกต้อง ไม่มี timezone หรืออนาคตเกินค่าผ่อนผัน
- ตลาดอื่นที่ไม่มีเวลาต้นทาง: unknown_timestamp ไม่ใช้ fetchedAt แทน

| ตัวแปรตั้งค่า | ค่าเริ่มต้น |
|---|---|
| PRICE_CURRENT_MAX_HOURS | 24 |
| PRICE_STALE_MAX_HOURS | 48 |
| PRICE_FUTURE_TOLERANCE_SECONDS | 0 |
| PRICE_ALLOW_UNKNOWN_TIMESTAMP | true |

allowUnknownTimestamp=true อนุญาตราคาตลาดอื่นที่คุณภาพผ่านแต่ไม่มีเวลาต้นทาง
ใช้เป็นราคาเปรียบเทียบ/ประวัติได้ แต่แสดง unverified_freshness และ verifiedCurrent=false
หากต้องการเฉพาะราคาที่พิสูจน์วันได้ ให้ตั้ง false; ความสามารถใช้ศรีเมืองอาจลดลง
ค่าตั้งผิดจะทำให้ startup แจ้งข้อผิดพลาด แทนการแอบเปลี่ยนนโยบาย
ยังไม่กำหนดสินค้าหลักทั้ง 10 พืช และไม่มีการเปลี่ยน URL/พารามิเตอร์ตลาด

Frontend แยกการรับข้อมูล API ออกจากจำนวนราคาที่ผ่านเกณฑ์ แสดง current/stale/
ไม่ทราบเวลา/โหลดไม่สำเร็จ รวมถึงเหตุผลขนาดที่เลือกใช้ไม่ได้ เวลาแสดงเป็น Asia/Bangkok

## ผลตรวจล่าสุด

ชุดทดสอบเดิม 74 กรณีคงสถานการณ์ไว้ แต่ปรับสองความคาดหวังตามนโยบายใหม่:
การบันทึกครั้งที่สองในวันเดียวกันต้องคืน false (ไม่เขียนทับ) และเมื่อสี่มุมเมืองโหลดล้มเหลว
แต่ศรีเมืองผ่านเกณฑ์ ให้บันทึกเฉพาะศรีเมืองได้ แทนการข้ามทั้งรอบ
sandbox ใช้เวลาควบคุมและฉีดตลาดจำลองผ่าน closure โดยไม่เปิดพอร์ตหรือเขียนประวัติจริง
เพิ่ม regression สำหรับคุณภาพทุกตลาด freshness, metadata, legacy history, no-retention-delete,
write failure และ render JSX จริง; เวลาทดสอบคงที่เพื่อไม่ให้ fixture เปลี่ยนผลตามวันที่รัน

ตลาดที่ยังไม่มีรหัส/ชื่อสินค้าจริง/ขนาด/เวลาต้นทางที่ตรวจได้ เก็บ null โดยไม่สร้างข้อมูลแทน
เกณฑ์ valid ในที่นี้ตรวจตัวเลขและหน่วยที่ adapter ส่งมา ไม่ยืนยันชนิด/เกรดหรือเวลาราคาของศรีเมือง
ส่วนการจัดเก็บประวัติยังเป็นไฟล์ JSON แบบเดิม ไม่ใช่ฐานข้อมูลสำหรับหลาย process เขียนพร้อมกัน
